## 4. 영역을 가로지르는 발견 → 설계 문서 반영 제안

각 파일 끝의 `새 축·규칙 후보` 절을 모은 것이다. 아직 설계 문서에 반영하지 않았다.

### 4.1 축과 분류
1. **S 축(보안·규제) 추가.** L0 위생(공개 콘텐츠만) / L1 기본(로그인·개인정보, 기본값) / L2 강화(결제 토큰화, B2B, 파일 업로드, 도구 호출 LLM) / L3 규제(카드번호 직접 처리, 주민번호·건강정보, 공공, ISMS 의무). [05]
2. **O(관측)는 독립 시나리오가 아니라 파생 수준 O0~O3.** 최대 필요 수준에서 정해지고, 2단계 넘게 높으면 과잉. §17.4를 확장. [07]
3. **수준과 무관한 위생 분류 `HYG`·`PERF`.** 인증서·도메인 만료, 타임아웃 기본값, N+1 등은 L0이어도 서비스를 멈춘다. [01, 02]
4. **D를 가용성(D-avail)과 데이터 복구(D-data)로 분리하는 안.** "재난 시 써야 하는 서비스"와 "데이터를 잃으면 안 되는 서비스"는 독립적이다. [01]

### 4.2 가정과 수준 정의 수정
5. **D 가정 수정 필요.** D L3 "RPO 1분 이하"는 PITR로 달성할 수 없다(RDS 트랜잭션 로그 업로드 5분 주기). D L2 "RPO 5분"은 경계값이다. 장애 범위(존/리전)별 RPO로 나누거나 L3에 교차 리전 연속 복제를 명시한다. [01]
6. **가정 추가:** `platform.plan`(Vercel·Supabase·GitHub 플랜에 따라 통제 충족이 갈림), 외부 공급자 한도(LLM 분당 토큰·월 지출 상한), 동시 연결 수(웹소켓·SSE). [01, 03, 08, 02]
7. **도메인 목록 확장:** §7.1의 9개 + AI/LLM, 교육·시험, 핀테크, 의료, 미디어, 게임·랭킹, IoT, 공개 API, 지도·위치, 랜딩·데모. 도메인별 기본 수준과 가정 표는 08의 파트 2. [08]

### 4.3 규칙 엔진 기능
8. **기본값 사실(`defaulted: true`)과 플랫폼 기본값 표.** "설정이 없음"이 곧 위험인 경우가 많다: Postgres `lock_timeout`·`statement_timeout` 0, uvicorn·Node keep-alive 5초 vs ALB 유휴 60초(간헐 502), GKE 드레이닝 기본 0초, CronJob `concurrencyPolicy: Allow`, CloudWatch Logs 무기한 보존, RDS API 생성 시 백업 1일. [02, 03, 06, 07]
9. **타이밍 부등식 규칙 종류:** `앱 keep-alive > LB 유휴`, `preStop ≥ LB 드레이닝`, `종료 유예 ≥ preStop + 요청 마무리`, `중복 제거 보존 기간 ≥ 상대 재시도 기간`(Stripe 웹훅 최대 3일, 토스 약 3일 19시간). [03, 04]
10. **용량 곱셈 규칙 종류(`capacity`):** "인스턴스 상한 × 단위 소비 ≤ 하류 한도"를 정적으로 판정하고 최악값 표를 자동 생성(simple-web-app `docs/deploy.md`의 커넥션 계산과 같은 형식). [02]
11. **사실 간 AND 조합, 묶음 처방(`co_requires`).** 예: readiness가 DB를 검사 AND 디그레이드 코드 있음 → 디그레이드가 사용자에게 닿지 않음. 선착순 이벤트는 T와 C 처방을 묶어서. [01, 02]
12. **라이브러리 버전별 판정:** Prisma 7과 8은 트랜잭션·증감 API가 달라 같은 코드 신호의 판정이 다르다 → `prisma.version` 같은 버전 사실. [04]

### 4.4 티어와 플랫폼
13. **AWS 티어 1 기본 경로를 ECS Express Mode로.** App Runner는 후보에서 제외. [08]
14. **티어 0 제외·경고 조건 추가:** Vercel Hobby 상업 이용 금지(결제 SDK가 있으면 $0 견적 불가), Hobby 크론 하루 1회, Supabase Free 1주 비활성 시 일시정지·백업 없음, Render Free DB 30일 만료, 디스크 붙인 Render·Fly 단일 인스턴스, 서버리스 HTTP 드라이버의 인터랙티브 트랜잭션 제약(C L3), Vercel 기본 리전 `iad1`(서울 DB와 대륙 간 왕복). [01, 04, 08]
15. **서버리스 손익분기:** 서울 가격 기준 1GB Lambda 100ms 요청은 월 약 2,200만 건(평균 약 8.5 rps)에서 Fargate 태스크 하나와 같아진다. 티어 선택의 비용 비교에 그대로 쓴다. [06]
16. **Cloud Run 요청 기반 과금에서는 응답 후 백그라운드 작업이 멈춘다.** Cloud Run GPU는 서울 미제공. [08]

### 4.5 비용
17. **비용 통제가 장애가 되는 반대 규칙:** Vercel 지출 한도 도달 시 팀의 모든 프로덕션이 일시정지(503). Supabase 지출 상한은 컴퓨트·PITR을 다루지 않음. [06]
18. **시간이 지나며 늘어나는 고정비:** EKS·RDS 연장 지원 요금, 로그 무기한 보존, 퍼블릭 IPv4 주소 과금, 서버리스 ElastiCache 최소 용량. [06]
19. **LLM 앱은 최악 시간당 비용과 사용자별 한도를 필수 출력으로.** 토큰 비용이 인프라 비용보다 훨씬 크고, 키 유출 시 상한이 없다. [06, 05]

### 4.6 검증 (P4)
20. **부하 생성기 유효성 게이트:** `dropped_iterations == 0`이고 생성기 CPU < 80%일 때만 판정에 쓴다. 운영과 다른 구성의 결과는 통제 상태를 바꾸지 못한다. [07]
21. **관측 통제도 `verify` 필수:** 장애 주입 때마다 기대한 알림이 몇 분 만에 왔는지 기록한다(지표가 끊기면 알림이 안 오는 설정 함정). [07]
22. **D×T 결합 장애 주입을 표준 시나리오로:** 재난 시 필수 서비스는 폭증과 인프라 장애가 동시에 온다. [01]
23. **U L2 핵심 검증을 "마이그레이션 적용 후 구버전 이미지로 통합 테스트"로 묶기:** DB뿐 아니라 API, 큐 메시지, 해시 청크, 세션 키 호환을 한 번에 본다. [03]
